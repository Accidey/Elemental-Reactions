# 2026-10-20

## 玩家报告 NoSuchFieldError: ModConfig$Type.COMMON 的定位结论

- 现象：玩家报 `net.neoforged.fml.ModLoadingException` → `elementalcraft` 加载失败，
  `java.lang.NoSuchFieldError: Class net.neoforged.fml.config.ModConfig$Type
  does not have member field '...Type COMMON'`；本地单模组测试正常。
- 根因（已查证）：NeoForge 26.3.0.37-beta 起执行了破坏性重命名
  （PR neoforged/NeoForge#3384，延续 FancyModLoader#436）：
  `ModConfig.Type.COMMON → LOCAL`，`ModConfig.Type.SERVER → SYNCED`。
  玩家用的是 ≥ 26.3.0.37-beta 的 NeoForge（日志行里能看到的 loader-12.0.8），
  本项目编译目标是 26.3.0.1-beta（FML 12.0.0，javap 验证枚举仍是 COMMON/CLIENT/SERVER/STARTUP）。
- 之所以没被依赖检查拦下：`neoforge.mods.toml` 的 `versionRange="[26.3.0.1-beta,)"` 是开区间。
- 受影响调用点（7 处，均需 COMMON → LOCAL）：
  - ElementalCraft.java:41
  - config/ElementalFireNatureReactionsConfig.java:1477
  - config/ElementalThunderFrostReactionsConfig.java:1224
  - config/ElementalVisualConfig.java:2354
  - config/ForcedItemConfig.java:66
  - util/ConfigAutoSync.java:103、112（`ConfigTracker.INSTANCE.loadConfigs(...)`）
- 同类已知案例：Balm 26.3.0.3、Waystones 均为此报错并修复；inventorysorter#212 报的是 SERVER 缺失。
- 尚未改代码（用户只要求定位）。后续升 neo_version 到最新 26.3.0.x 时，
  26.3.0.45（DeferredHolder 继承 Holder.Reference）、26.3.0.52（HolderExtension#key 改为抛异常）、
  26.3.0.53（VersionChecker 移出 FML）、26.3.0.65（patch cleanup breaking changes）可能带来额外编译错误。
